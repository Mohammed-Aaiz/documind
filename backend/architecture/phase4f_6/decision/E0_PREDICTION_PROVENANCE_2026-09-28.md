# E0 Prediction Provenance — answer-text decoder defect (recorded 2026-09-28)

> **Read this before quoting any EM/F1 value from an E0 artifact.**
> The E0 evaluation artifacts were produced from `model_40min_predictions.json`,
> whose answer **text** was generated by `tokenizer.decode()`. That decoder
> re-inserts spaces at subword boundaries and corrupted every value the
> tokenizer split. All EM/F1 values in those artifacts are therefore
> **pre-fix** values that understate accuracy. The models, the logits, the
> selected spans, the scores and the thresholds are **not** implicated.

## 1. What was wrong

`tokenizer.decode(input_ids[start:end+1], skip_special_tokens=True)` re-joins
WordPiece tokens with inserted spaces, so a span the model predicted as one
value came back mangled:

| source text | recorded prediction |
|---|---|
| `142.6 million` | `142. 6 million` |
| `$4,900` | `$ 4, 900` |
| `2011-2020` | `2011 - 2020` |
| `89,000` | `89, 000` |
| `22.1%` | `22. 1 %` |

The tokenizer's `return_offsets_mapping=True` output points each token back into
the source string, so slicing the original context reproduces the document's
literal characters. That is the fix, implemented **once** in
`backend/answer_span.py` and used by both `chat/qa_model.py` (production QA) and
every Phase 4F runner.

## 2. What this does and does not invalidate

**Not affected — verified, not assumed.** The fix changes answer *text* only.
The predicted span, the start/end logits, the softmax scores, `null_score`,
`margin`, the confidence value and every threshold are byte-identical before and
after. This was measured directly by running the git-original implementation and
the fixed implementation side by side on the same inputs: all 7 probe cases
returned identical `score` and identical `(start, end)` spans and differed only
in the answer string. Therefore:

- **logit/score-derived results stand**: `null_score` distributions, `margin`,
  AUCs, discrimination/calibration statistics, the recorded G threshold
  (`null_score >= 1.5705`), and the fixed-K ranking experiments' *rankings*.
- **anything keyed on the answer text does not stand**: EM, F1, and the recorded
  per-example `em` flag inside the predictions artifact (which is itself computed
  from answer text).

## 4. Measured size of the effect

Same 182 frozen examples, same checkpoints, same spans, **only the decoder
changed** (re-run 2026-09-28, `phase4f_5f/f2/threshold_experiment`):

| quantity | recorded (pre-fix) | re-run (fixed) |
|---|---|---|
| F2 answerable EM (gate `null_score>=1.5705`) | 2.86% | **14.29%** |
| F2 answerable F1 | 16.92% | **28.91%** |
| F2 validation EM | 5.88% | **20.0%** |

A0 and A1/A2 move the same way (A0 EM 2.1% → 7.9%; A1 3.6% → 15.7% on the same
182). A string-level estimate of the same effect, reproducible from the recorded
artifact, is in `RECONSTRUCTION_BOUND.{json,md}`.

**Operating-point clarification (added 2026-09-28, matters for comparisons).**
The `2.86% → 14.29%` pair above is the **gated** operating point
(`null_score >= 1.5705`). The **ungated** answerable EM on the same 182 examples
moves `4/140 (2.86%) → 21/140 (15.0%)`. Both are the same effect measured at
different operating points; the gated pre-fix value happens to equal the ungated
one (the gate abstained only on already-incorrect examples). The reproducible
string-level estimate in `RECONSTRUCTION_BOUND.json` reproduces the **ungated**
`21/140` exactly — so an earlier reading of that estimate as "one example too
high" was a gated-vs-ungated comparison error, now corrected.

**No generalisation claim attaches to any of these numbers.** Every population
used here is fully leaked — the 182 benchmark examples all appear in
`training_data.jsonl` and `training_data_v3.jsonl`. This is a decoder experiment
on training-set data, not a model quality result.

## 5. Why the input predictions were not regenerated

`model_40min_predictions.json` (sha256 `d7d9d65e944488ac...`) was **left
untouched**:

- nothing in the repository produces it (it was generated by a runner that is not
  present), so it cannot be regenerated faithfully;
- its re-scoring tools and the artifacts above pin its sha256, so replacing it
  would silently break that evidence chain rather than repair it;
- regenerating it would change a frozen E0 input without a recorded protocol.

Consequently the affected EM/F1 values above remain pre-fix on disk. The honest
position is that they are **superseded**, not corrected: use the re-run numbers
in `phase4f/phase4f_5f/f2/threshold_experiment/` (or re-run
`tools/reconstruction_bound.py`) for any post-fix EM/F1 statement, and keep
quoting the originals only as the pre-fix record.

## 6. Remediation path (not yet done)

1. Locate or rebuild the producer of `model_40min_predictions.json`, regenerate
   it with the fixed decoder, and re-issue the affected artifacts under a new
   dated hash — a separate, explicitly-scoped task.
2. Build a genuinely leakage-free held-out set before any of these numbers are
   used to argue that the model is good.
