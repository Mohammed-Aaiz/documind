# E0 ERRATUM — Phase 4F.6 corrections

**Date:** 2026-09-27 · **Nature:** correction/erratum **only** — no E0 execution, no SQL, no
database contact, no server start, no re-measurement. This document does not re-adjudicate
the E0 gate and does not revise any measurement, fingerprint or count produced by Phase 4F.6.

**Applies to:** `backend/architecture/phase4f_6/**` (Phase 4F.6-B … 4F.6-G).

---

## 1. Why this erratum exists

Phase 4F.6 recorded several statements **about the state of this repository** that are
inaccurate. They were then used as premises for the phase's blocker classifications, so
readers (human or agent) can be misled about where DocuMind's database actually is and
whether a migration environment exists.

Nothing was fabricated when those documents were written — the probes simply looked in the
wrong places (e.g. globbing for a directory literally named `alembic/` rather than
`backend/migrations/`), and the database target was inferred from `backend/.env.example`
and `backend/config.py` defaults rather than from the actual `backend/.env`.

**The bodies of the affected documents are preserved unaltered.** They are the historical
record of what Phase 4F.6 did and concluded. This erratum is the correction layer, and it
is authoritative wherever it disagrees with them.

## 3. Claims checked and found still accurate (no over-correction)

These were verified during the same pass and are **not** changed:

- Vector store is **pgvector**, with `document_chunks.embedding` as `Vector(384)`
  (`backend/documents/models.py`); cosine distance via `1 - (dc.embedding <=> CAST(:e AS vector))`
  (`backend/chat/rag.py`).
- The substitute ban is correct and remains in force: no SQLite, no FAISS, no in-memory
  cosine search for the production retrieval path.
- Embedding model `all-MiniLM-L6-v2` at 384 dimensions (`backend/embeddings/model.py`).
- The QA model is the project's own trained DistilBERT, default `./models/documind-qa`
  (`backend/chat/qa_model.py`); the Python `pgvector==0.5.0` package is a type adapter and
  **not** the server extension.
- The corpus fingerprints, chunk counts (93/93, 6/6) and provenance results reported by
  4F.6-D/E are untouched by this erratum — they are measurements, not environment claims.
- The `E0_RETRIEVAL_RUNTIME_BLOCKED` classification is **not** re-adjudicated here. What is
  corrected is the *reasoning and attribution* about the environment, not the gate decision.
  Re-opening or closing that gate is a separate, explicit decision.
