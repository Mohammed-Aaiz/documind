# 4-bit inference for the instruct conversation model (generation/causal.py).
# These packages do nothing unless torch reports a CUDA device; on a CPU-only
# torch, causal.plan_loading() selects the float32 CPU path and reports why.
# A CUDA-enabled torch build is therefore required for 4-bit loading, e.g.
#   pip install --no-deps --index-url https://download.pytorch.org/whl/cu126 \
#       "torch==2.13.0+cu126"
# `--no-deps` is deliberate: it keeps the pinned torchvision 0.28.0, which
# declares torch==2.13.0 (PEP 440 ignores the `+cu126` local label when
# matching `==2.13.0`).
# Measured 2026-10-22 on an RTX 3050 Laptop (4 GB): torch 2.13.0+cu126 +
# bitsandbytes 0.50.2 loads Qwen2.5-1.5B-Instruct in NF4 at 1154 MiB allocator
# peak / 1274 MiB driver-reported (scripts/measure_conversation_vram.py).
bitsandbytes==0.50.2
accelerate==1.15.0

# Voice transport — WebRTC (POST /api/voice/webrtc/offer).  aiortc carries the

# Voice TTS — local Piper voice is the default engine (POST /api/voice/synthesize,
# the WebRTC call's audio track).  Synthesis runs on the already-pinned onnxruntime CPU
# provider: no network, no VRAM.  piper-tts wheels bundle their own espeak-ng
# data, so no system-level espeak-ng install is required.  The engine is
# GPL-3.0 — fine for server-side use; revisit before distributing a bundled

# (voice dataset: LJSpeech, public domain).
