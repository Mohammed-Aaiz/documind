14. OVERFITTING ANALYSIS
======================================================================

  A1 (DistilBERT):
    Training loss: 5.36 -> 3.95 -> 3.62 (decreasing — learning)
    Val EM: 0.0% -> 0.0% -> 0.0% (never learned to extract)
    Val F1: 4.1% -> 5.3% -> 5.0% (marginal)
    Diagnosis: Model is learning loss landscape but NOT learning
    to extract correct spans. Possible catastrophic forgetting
    of pretrained QA ability.

  A2 (BERT-base):
    Training loss: 5.52 -> 4.15 -> 3.61 (decreasing — learning)
    Val EM: 0.0% -> 0.0% -> 0.0% (never learned)
    Val F1: 2.2% -> 4.2% -> 2.9% (noisy, no improvement)
    Diagnosis: Same pattern as A1. Loss decreases but extraction
    capability does not emerge.

  A3 (DeBERTa-v3):
    Training loss: nan -> nan -> nan (complete instability)
    Diagnosis: Training collapsed from epoch 1. NaN loss indicates
    gradient explosion or numerical instability. Model never learned.

  ROOT CAUSE ANALYSIS:
  The QA head (qa_outputs) is randomly initialized. With 918 examples
  and only 3 epochs, the randomly initialized head cannot learn to map
  pretrained representations to correct answer spans. The pretrained
  model's existing span selection ability is being overwritten by the
  random head before it can be fine-tuned.

  This is a known issue with extractive QA fine-tuning:
  - The randomly initialized qa_outputs layer dominates gradient flow
  - With limited data (918 examples), the pretrained representations
    are destroyed before useful span selection emerges
  - The production model likely had extensive pre-training or different
    initialization that preserved these representations

18. LIMITATIONS
======================================================================

  1. The evaluation uses the SAME data the models were trained on.
     This measures memorization, not generalization.
     True generalization requires held-out external data.

  2. The production model (A0) was NOT trained with this pipeline.
     It likely used a different training regime, more data, or
     different initialization. Direct comparison is limited.

  3. A3 (DeBERTa) suffered training instability (nan loss).
     This could be due to:
     - Learning rate too high for DeBERTa without warmup tuning
     - Gradient instability without fp16 (which was disabled)
     - Insufficient data for DeBERTa's capacity

  4. The qa_outputs head is randomly initialized for A1/A2/A3.
     The production model may have been initialized differently.

  5. Only 3 epochs with 918 examples may be insufficient for
     fine-tuning to emerge, especially with random head initialization.

  6. ECE and Brier score are NOT implemented in evaluate.py.

======================================================================
19. FINAL EXPERIMENTAL CONCLUSION
======================================================================

  EXPERIMENTAL OUTCOME: NO_MEANINGFUL_IMPROVEMENT

  Evidence:
  - ALL trained models (A1, A2, A3) perform WORSE than A0 baseline
  - A1 (DistilBERT): EM dropped from 7.8% to 0.7% (-7.1pp)
  - A2 (BERT-base): EM dropped from 7.8% to 0.0% (-7.8pp)
  - A3 (DeBERTa-v3): Training collapsed (nan loss), model non-functional
  - A0's strengths (DATE 96%, ENTITY 63.6%) were DESTROYED by fine-tuning
  - All trained models hallucinate on unanswerable questions (4.6% spurious)
  - Confidence signals remain uninformative across all models

  ROOT CAUSE:
  Random initialization of the QA head combined with limited training
  data (918 examples, 3 epochs) causes catastrophic forgetting of
  pretrained span selection ability. The models learn to reduce loss
  but never learn to extract correct answer spans.

  RECOMMENDATION:
  NO production change. The current fine-tuning approach is not viable.
  Future investigation should consider:
  - Initializing qa_outputs from the production model
  - Using more epochs with lower learning rates
  - Curriculum learning or multi-stage training
  - Larger datasets with more diverse examples
  - Proper warmup and learning rate scheduling for DeBERTa
