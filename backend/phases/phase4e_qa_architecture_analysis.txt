8. TABLE ANALYSIS
==============================================================================

  TABLE_CELL: Answer in single cell — PARTIALLY extractive
  TABLE_ROW: Interpret one row — PARTIALLY extractive
  TABLE_COMPARISON: Compare values — NOT extractive
  TABLE_AGGREGATION: Calculate from table — NOT extractive

  Current table performance (unified oracle): 29.2% EM
  The model CAN extract table cells when evidence is sufficient,
  but CANNOT navigate row/column relationships reliably.

10. MULTI-CHUNK ANALYSIS
==============================================================================

  Multi-chunk questions require evidence from multiple chunks.
  The extractive QA model receives ONE concatenated context,
  so multi-chunk is PARTIALLY representable if all evidence
  fits in the 384-token window.

  1 multi-chunk question in corpus: 100% failure rate
  This is too few samples to draw conclusions.

14. EXTRACTIVE ARCHITECTURE ANALYSIS
==============================================================================

  Current architecture: DistilBertForQuestionAnswering
    - 66M parameters, 6 layers, 12 heads, 768 dim
    - Max input: 384 tokens
    - Extractive span prediction (start/end logits)
    - ~23ms latency on CPU

  Strengths:
    - Fast inference (~23ms)
    - Deterministic output
    - Inherent span provenance (answer position in context)
    - No hallucination risk
    - Simple deployment

  Limitations:
    - Cannot synthesize across chunks
    - Cannot compare values
    - Cannot aggregate or calculate
    - Cannot reason about list order
    - Single contiguous span only
    - 384-token context window
