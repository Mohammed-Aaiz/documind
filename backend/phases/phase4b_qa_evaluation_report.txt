5. QUESTION TAXONOMY
================================================================================

Questions test the following QA behaviors:
  - Direct span extraction (factual questions)
  - Numeric extraction (dates, measurements, percentages)
  - Entity extraction (names, organizations)
  - Table cell lookup (specific row/column intersection)
  - Table row lookup (finding the correct row)
  - Table comparison (which has highest/lowest)
  - List-item lookup (specific item in a list)
  - List ordering (which item follows X)
  - Section-specific extraction (from a specific section)
  - Multi-chunk extraction (information across pages)
  - Surrounding-context extraction (context around the answer)
  - Definition questions (what is X)
  - Comparative questions (which is larger)
  - Unanswerable questions (no supporting evidence)

================================================================================
6. GOLD EVIDENCE METHODOLOGY
================================================================================

For every answerable question:
  - expected_answer: deterministic gold answer
  - acceptable_answers: paraphrase variants
  - evidence: distinctive substrings that must appear in supporting chunks
  - kind: question category
  - document: source document

Evidence is established from the document builders (programmatic,
deterministic).  No fuzzy matching or semantic similarity is used
as the primary correctness criterion.

================================================================================
13. TABLE ANALYSIS
================================================================================

24 table questions across 7 documents.
Failure rate: 95.8% (23/24)

Root causes:
  A. Representation (16/23): Pipe-delimited serialization destroys
     row/column structure that the extractive model needs.
  B. Context ordering (4/23): Evidence omitted from QA context
     (EVID_OMIT) despite being retrieved.
  C. Context truncation (3/23): Table text exceeds QA context window.

The table representation problem is the #1 cause of table failures.
The pipe-delimited format ("Method | Result") is treated as continuous
prose by the tokenizer, making row boundaries invisible.

================================================================================
14. LIST ANALYSIS
================================================================================

16 list questions across 3 documents.
Failure rate: 93.75% (15/16)

Root causes:
  A. Retrieval miss (8/16): List items not retrieved.  The legacy
     chunker splits lists across chunks, and even structure-v2
     sometimes fails to preserve list item boundaries in embeddings.
  B. QA extraction (7/16): List items retrieved but wrong span
     extracted.  Ordinal questions ("which follows X?") require
     reasoning that extractive QA cannot perform.

List questions are the WORST performing category.  The pipeline
fundamentally cannot handle list-based content.

16. CONTEXT ANALYSIS
================================================================================

EVID_OMIT: 10 failures (10.9%)
  Evidence retrieved but not supplied to QA.  The 384-token QA window
  cannot accommodate all relevant chunks.  Structure-v2 produces larger
  chunks (median 34 tokens vs 13), so fewer chunks fit.

CTX_TRUNC: 5 failures (5.4%)
  Context overflow.  The QA context exceeds the 384-token window.
  Primarily affects table and long-paragraph documents.

Context utilization: 0.98 (Arm C) — nearly full on average.

21. BOTTLENECK DECISION
================================================================================

Based on Phase 4B evidence:

  #1 QA MODEL (33 failures, 35.9%)
     Table and list failures dominate.  The extractive model cannot
     handle structured content.  Training data mismatch confirmed.

  #2 RETRIEVAL (15 failures, 16.3%)
     Significant retrieval failures on list and factual questions.
     The embedding model struggles with short list items and
     unpunctuated text.

  #3 CONTEXT CONSTRUCTION (10 failures, 10.9%)
     Evidence omission and context truncation affect table and
     long-paragraph questions.

The QA model remains the #1 bottleneck, but retrieval is now a
significant secondary bottleneck that Phase 3F did not reveal.

23. RECOMMENDED PHASE 4C

Based on Phase 4B evidence, the recommended next phase is:

  PRIMARY: Expand evaluation with REAL documents
    - Acquire 10+ legally sourced real documents
    - Validate that synthetic results correlate with real performance
    - This is BLOCKING — no model changes without real validation

  SECONDARY: Address retrieval failures (15 RET_MISS)
    - Investigate why list items are not retrieved
    - Consider list-aware embedding or retrieval strategies
    - This is a NEW finding from Phase 4B

  TERTIARY: QA model improvement (table/list training data)
    - Add table QA training data (pipe-delimited serialization)
    - Add list/ordinal training data
    - Address 33 QA_EXTRACT failures

  DEFERRED: Structure-v2 production promotion
    - NOT supported by Phase 4B evidence
    - Requires broader validation with real documents

  NOT RECOMMENDED: Generative QA, Retrieval V2, hybrid search
    - No evidence supporting these changes
