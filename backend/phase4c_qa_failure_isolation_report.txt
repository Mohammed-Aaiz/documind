## 1. EXECUTIVE SUMMARY

Phase 4C isolates the causal failures in DocuMind's QA pipeline through controlled
offline experiments. The central finding is unambiguous:

**The QA model fails on 84.3% of questions even when given the EXACT gold evidence.**

This proves that the dominant failure is NOT retrieval, NOT context construction,
NOT representation — it is the QA model's inability to extract correct spans from
text, particularly for tables, lists, numeric answers, and multi-sentence contexts.

### Key Numbers

| Experiment | Result | Implication |
|---|---|---|
| Oracle evidence (exact gold) | 8/51 pass (15.7%) | QA model is primary bottleneck |
| Table R4 (gold representation) | 0/23 pass (0%) | Tables are model limitation, not representation |
| List R3 (minimal representation) | 1/15 pass (6.7%) | Lists are model limitation, not representation |
| RET_MISS with oracle | 15 failures still fail | Retrieval misses are real but secondary |
| Confidence overlap | [0.0147, 0.4484] | Confidence is NOT usable for gating |

### Primary Conclusion

**TASK_ARCHITECTURE_MISMATCH** — DistilBERT extractive QA cannot reliably handle
tables, lists, numeric extraction, or multi-sentence synthesis. The model architecture
is fundamentally misaligned with DocuMind's document types.

and cannot establish the row/column relationships needed to extract "90%".

### 9.4 Span Selection Diagnosis

The DistilBERT extractive QA model:
1. Computes start/end logits for every token position
2. Selects the span with highest start+end score
3. Has NO understanding of table structure, list ordering, or numeric relationships
4. Often selects the span with the highest individual token score rather than the best span

**Classification:** MODEL_SPAN_SELECTION is the dominant failure mode.

### 17.2 Phase 4D Scope

**Option A: Fine-tune current DistilBERT with table/list data**
- Addresses: training data gap
- Does NOT address: architecture limitation
- Expected improvement: moderate on tables/lists, none on synthesis
- Risk: may not be sufficient

**Option B: Replace with larger extractive model (DeBERTa-v3-large)**
- Addresses: model capacity
- Does NOT address: architecture limitation for synthesis
- Expected improvement: moderate
- Risk: same fundamental limitation

**Option C: Replace with generative QA model**
- Addresses: architecture limitation
- Handles: tables, lists, synthesis, reasoning
- Expected improvement: significant
- Risk: explainability, evidence grounding, latency
- **RECOMMENDED**

### 17.3 Recommended Phase 4D Acceptance Criteria

1. Expand evaluation to 150+ questions
2. Add real-world documents where legally sourced
3. Prototype generative QA with evidence grounding
4. Measure: exact match, F1, answerability, confidence calibration

8. No production deployment
